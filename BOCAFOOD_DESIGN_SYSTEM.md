# BocaFood Design System

Documento oficial de identidade visual, linguagem visual e padrões de layout do BocaFood.

Este arquivo é a referência principal para futuras alterações no painel interno e nas telas administrativas. Quando houver dúvida visual, este documento prevalece.

## 1. Objetivo visual

O BocaFood deve parecer uma plataforma premium gastronômica, moderna, sofisticada, acolhedora e humana.

O sistema precisa transmitir:
- confiança
- clareza
- controle
- refinamento
- maturidade visual
- eficiência operacional
- calor humano sofisticado

## 2. Direção visual da marca

A direção visual do BocaFood é food-tech premium.

O painel deve unir:
- a organização de um SaaS moderno
- a densidade útil de ferramentas profissionais
- a elegância de interfaces premium
- a sensibilidade visual de marcas gastronômicas bem acabadas

## 3. Conceito central

O conceito oficial é:

**food-tech premium**

Isso significa:
- menos aparência de software frio
- menos aparência de ERP antigo
- menos aparência de dashboard financeiro genérico
- mais sofisticação
- mais suavidade
- mais leitura editorial
- mais coerência visual

## 4. O que o sistema deve transmitir

O BocaFood deve transmitir:
- produto real
- operação séria
- organização
- precisão
- cuidado
- visual limpo
- presença premium
- sensação de marca sólida

## 5. O que o sistema NÃO deve parecer

O BocaFood não deve parecer:
- ERP antigo
- sistema financeiro frio
- dashboard corporativo genérico
- painel administrativo pesado
- interface inflada por caixas
- software técnico sem calor visual

## 6. Filosofia visual

A filosofia do BocaFood é:

**minimalismo quente premium**

Isso significa:
- remover excesso antes de adicionar elementos novos
- manter respiro
- priorizar leitura
- evitar ruído visual
- usar cor com intenção
- preservar densidade equilibrada
- desenhar com refinamento, não com excesso

## 7. Referências conceituais

Referências de orientação:
- Nuvemshop: clareza, estrutura e leveza
- Shopify: sofisticação e escala visual
- Apple: refinamento, silêncio visual e acabamento
- Tiny / Olist: densidade, alinhamento e eficiência
- Hospitality design: acolhimento, elegância e calor controlado

Estas referências são conceituais. O BocaFood deve seguir a intenção visual, não copiar telas literalmente.

## 8. Sistema tipográfico oficial

### Fonte principal

`Manrope`

### Fallbacks

`Inter`, `sans-serif`

### Pesos permitidos

- `400`
- `500`
- `600`

### Pesos a evitar

- `700`
- `800`
- bold excessivo

### Escala tipográfica oficial

- Título principal: `32px / 600 / line-height 1.1`
- Subtítulo: `15px / 400 / line-height 1.5`
- Título de seção: `18px / 600`
- Título de card: `14px ou 15px / 600`
- Texto padrão: `14px / 400`
- Texto secundário: `13px / 400`
- Label auxiliar: `12px / 500`
- Sidebar: `14px / 500`
- Tabela: `14px / 400`
- Nome do produto: `15px / 600`
- KPI numérico: `38px / 700 visual equilibrado`
- KPI label: `13px / 500`
- Botões: `14px / 500`
- Chips/status: `12px / 500`

### Regras tipográficas

- usar line-height confortável
- evitar texto muito colado
- reduzir contraste excessivo em textos secundários
- usar uppercase com cautela e apenas em labels, cabeçalhos ou microcópias
- não espalhar uppercase por toda a interface
- manter hierarquia clara sem peso exagerado

## 9. Paleta oficial

### Base

- Fundo principal: `#FFFFFF`
- Variação de fundo muito suave: `#FAFAF8`
- Cards: `#FFFFFF`
- Bordas: `#EAE4DA`
- Texto principal: `#1F1F1F`
- Texto secundário: `#6F6860`
- Texto suave: `#A39B90`

### BocaFood

- Vermelho principal: `#D71920`
- Vermelho hover: `#B9151B`
- Vermelho claro / ativo: `#FDECEC`
- Vermelho borda suave: `#F7CACA`

### Dourado sutil

- Dourado premium: `#B6925E`
- Dourado suave: usar apenas em microdetalhes

### Regra de cor

- a base deve ser clara e limpa
- evitar aparência azulada corporativa
- evitar bege pesado
- usar vermelho com controle
- usar dourado quase imperceptível

## 10. Filosofia de sombras

As sombras existem para criar profundidade leve, não para dramatizar a interface.

### Sombras oficiais

- Card padrão: `0 12px 30px rgba(31,31,31,0.06)`
- Superfície elevada: `0 16px 40px rgba(31,31,31,0.12)`
- Elementos pequenos: `0 1px 2px rgba(31,31,31,0.04)`

### Regras

- usar sombras suaves
- evitar sombra forte em cards comuns
- não criar sensação de flutuação excessiva
- sombra deve ajudar a leitura, não virar decoração

## 11. Radius oficiais

- Cards principais: `16px`
- Botões: `10px`
- Inputs / selects: `10px`
- Chips / status: `999px`
- Modais: `20px`
- Sidebar item: `10px`
- Mini-botões e ações: `9px` a `10px`

## 12. Espaçamentos oficiais

### Escala base

- `4px`
- `8px`
- `12px`
- `16px`
- `20px`
- `24px`
- `32px`
- `40px`

### Regras de aplicação

- padding desktop da página: `32px`
- padding tablet: `20px`
- padding mobile: `16px`
- espaço entre blocos grandes: `24px`
- gap entre cards: `16px`
- padding interno de cards: `20px` ou `24px`
- espaço entre título e conteúdo: `12px`

## 13. Regras da sidebar

### Estrutura

- fundo branco
- borda direita suave
- logo no topo
- navegação simples e clara
- submenus discretos

### Visual

- ícones pequenos e elegantes
- textos com peso moderado
- item ativo com fundo vermelho claro
- subitem ativo com indicador discreto
- evitar caixas pesadas dentro da sidebar

### Rodapé da sidebar

- dados da loja devem ser compactos
- ajuda deve ser discreta
- sair deve ser pequeno e não dominante

### Exemplo de comportamento

- `Cardápio` ativo: destaque suave, sem parecer botão grande
- `Produtos` ativo: indicador fino, discreto, elegante
- bloco de ajuda: card pequeno, sem poluição visual

## 14. Regras da topbar

- altura controlada
- fundo branco
- borda inferior suave
- breadcrumb pequeno
- ação principal à direita quando necessário
- evitar excesso de botões no topo
- reduzir ruído visual

## 15. Regras de KPIs

KPIs devem ser:
- claros
- expressivos
- compactos
- sofisticados

### Regras

- card em branco ou off-white muito suave
- sem borda pesada
- sem texto decorativo no fundo
- ícone maior quando fizer sentido
- número com presença
- label discreta
- alinhamento preciso

### Exemplos

- `Total de produtos`
- `Categorias`
- `Produtos visíveis`
- `Pedidos (30 dias)`

## 16. Regras de filtros

Filtros devem parecer uma barra premium, não um formulário pesado.

### Regras

- um card único
- inputs alinhados
- labels discretas
- altura consistente
- botão de filtros integrado
- botão limpar discreto
- chips de resultado sutis
- evitar excesso de selects soltos

### Exemplo de composição

- busca
- categoria
- visibilidade
- ordenação
- filtros adicionais
- limpar filtros

## 17. Regras de tabelas

Tabelas devem ser limpas, densas e elegantes.

### Regras

- cabeçalho branco
- separador fino e discreto
- títulos das colunas em uppercase leve
- linha com hover suave
- espaçamento vertical equilibrado
- ações pequenas e discretas
- chips com contraste moderado
- paginação no rodapé

### Exemplo de colunas

- Produto
- Categoria
- Preço
- Status
- Destaque
- Ações

## 18. Regras de botões

### Primário

- vermelho BocaFood
- texto branco
- altura `40px`
- radius `10px`
- sombra sutil

### Secundário

- fundo branco
- borda suave
- texto principal
- visual leve

### Fantasma

- sem fundo
- usado para ações menores
- discreto

### Excluir

- nunca deve parecer ação principal
- vermelho controlado
- uso contextual

## 19. Regras de chips

Chips devem servir para resumo, status e sinalização.

### Regras

- bordas suaves
- fundo branco ou muito leve
- texto pequeno e claro
- sem visual pesado
- sem saturação excessiva

### Exemplos

- `Ativo`
- `Oculto`
- `Destaque`
- `Sem categoria`
- `Página 1 de 3`

## 20. Filosofia visual geral

O BocaFood precisa de:
- silêncio visual
- refinamento
- alinhamento
- consistência
- densidade equilibrada
- hierarquia clara

### Silêncio visual

Silêncio visual é reduzir ruído, excesso de contorno, excesso de cor e excesso de informação visível ao mesmo tempo.

### Refinamento

Refinamento é cuidar de proporção, espaçamento, borda, contraste e ritmo sem chamar atenção para o próprio estilo.

### Alinhamento

Tudo deve parecer intencional:
- ícones alinhados
- textos alinhados
- cards alinhados
- ações alinhadas

### Consistência

Quando um padrão for criado, ele deve ser reaproveitado.

### Densidade equilibrada

O painel pode ser denso, mas não cansativo.
Ele deve ser útil, escaneável e elegante.

## 21. Regras quando houver dúvida visual

Se houver dúvida entre adicionar ou remover:

**remover primeiro**

Regra prática:
- remover antes de adicionar
- simplificar antes de decorar
- clarear antes de saturar
- alinhar antes de expandir

## 22. Princípios de consistência

- não criar estilos novos sem necessidade
- reaproveitar padrões já existentes
- não misturar muitas famílias de cor
- não usar bold excessivo
- não misturar muitas escalas tipográficas
- não aumentar a complexidade visual por hábito
- não alterar estrutura funcional sem pedido

## 23. Exemplos de uso

### Exemplo de página boa

- título claro
- subtítulo curto
- ações à direita
- KPI compacto
- filtro limpo
- tabela clara
- chips discretos

### Exemplo de componente bom

- card branco
- borda suave
- sombra leve
- tipografia Manrope
- cor usada com intenção
- ícone pequeno ou proporcional

## 24. Aplicação por módulos

A aplicação do padrão deve acontecer por módulo ou por aba, não em todo o sistema de uma vez.

Ordem sugerida:
1. Cardápio
2. Financeiro
3. Compras
4. Produção
5. Pedidos
6. Clientes
7. Configurações
8. Master

## 25. Regra final

Se uma nova tela, card, modal ou tabela não parecer:
- premium
- clara
- humana
- alinhada
- coerente
- silenciosa

então o padrão deve ser refeito antes de seguir.
