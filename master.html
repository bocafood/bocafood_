Abrir Centro de Control
Este painel deve ser aberto pelo servidor local em 127.0.0.1. Ações internas ficam bloqueadas fora desse contexto.

Usuários cadastrados

Usuário é o dono do Centro de Control e da loja publicada. Clientes da loja ficam separados dentro da base desse usuário.

E-mails automáticos

Configure SMTP, templates transacionais, prévias responsivas e testes internos do BocaFood.

Publicar site

Publica o pacote público completo do site para um tenant específico. Repositório e branch são lidos do cadastro.

Se o campo ficar vazio, o Master usa o token salvo no cadastro do usuário. Crie em GitHub → Settings → Developer settings → Personal access tokens (permissão repo).

Publicar todos os sites

Publica o pacote público completo para todos os tenants ativos que têm repositório GitHub configurado no cadastro.

O repositório e a branch de cada tenant são lidos do cadastro (aba Usuários). Tenants sem repositório configurado são ignorados.

Configurações Globais

Tipos padrão compartilhados por todos os tenants para o módulo financeiro.

Esses registros vivem no Master e são usados pelos selects do Admin financeiro. O tenant apenas escolhe entre os tipos compatíveis com o seu país fiscal.

Backup do Sistema

Área interna para verificar alterações locais e enviar o código do Master para um repositório GitHub privado.

Clique em “Verificar alterações” para ver branch, commit e arquivos alterados.

Dados Firestore

O backup automático oficial do Firestore exige plano Blaze/billing ativo. Quando o sistema tiver usuárias reais, ative o Blaze e configure backup agendado para Cloud Storage.

Nesta etapa não será feita exportação oficial do Firestore.
